# 目标
在信息获取方式（指通过问诊、要求检查）**不变**的前提下，实现更高的准确率
严禁直接使用完整信息，信息获取流程必须跟普通doctor保持完全一致，仅优化处理信息的过程。 

# 设计
1. 调用llm，根据已知信息，给出数种可能的疾病种类（由一参数限制最大数量）
2. 调用llm，根据已知信息和1.中得到的疾病种类列表，给出诊断计划，计划指一个由问诊或检查组成的有序步骤列表，尽可能先进行区分度高、成本低的步骤（一般为问诊）。若为问诊，则给出该问诊的目标信息（例如“是否有发热”）；若为检查，则给出该检查的名称（例如“血常规”）
3. 执行2.中诊断计划的首项，若为问诊，则调用llm进行问诊（输入为情境和目标信息等）；若为检查，则不需要调用llm，直接输出检查请求（格式为"REQUEST TEST: [test]"）。完成后该项标记为已完成
4. 若3.中得到有效的问诊结果或检查结果，调用llm，更新合并已知信息；否则，回到3.
5. 根据4.中更新后的已知信息，对之前1.中得到的疾病种类列表，更新每种疾病的确诊概率（confidence）
6. 根据4.中更新后的已知信息，重新进行1.，比较新的疾病种类列表与之前的疾病种类列表的差异，若新列表缺少的某种疾病目前的confidence低于某个阈值，则可认为此疾病已被排除；若新列表中出现了某种新疾病，则需要调用llm重新进行2.，更新诊断计划。注意，新增/减少的判断应由llm进行，避免对同一疾病不同表述的名称差异导致误判
7. 当某种疾病的confidence超过某个阈值，则该疾病确诊，输出诊断结果（格式为"DIAGNOSIS READY: [diagnosis here]"）；或者达到最大问诊次数时仍无法确诊，则结束流程，输出当前confidence最高的疾病作为诊断结果
