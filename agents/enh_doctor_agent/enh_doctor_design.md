# 目标
在信息获取方式（指通过问诊、要求检查）**不变**的前提下，实现更高的准确率
严禁直接使用完整信息，信息获取流程必须跟普通doctor保持完全一致，仅优化处理信息的过程。 

# 设计
1. 调用llm，根据已知信息I（由数条{操作o, 目的g, 结果i}构成的信息对构成的集合），给出数种可能的疾病种类d构成的有序集合H（最少一种，最大数量由一参数限制），要求给出的疾病不得与已知信息存在明显冲突，顺序表示可能性大小（最可能的在前），无需输出可能性值
2. 若1.给出的疾病集合H中仅包含一种疾病d，调用llm，基于已知信息I和疾病d，给出详细分析，包含已确认的支持d的证据，尚未确认的可能支持或反对d的证据（若存在）
3. 若1.给出的疾病集合H中包含多种疾病，则截取前两种疾病d1,d2，调用llm，基于已知信息I和疾病d1,d2，给出区分d1和d2所欠缺的关键信息
4. 调用llm，基于已知信息I和2.或3.的结果，给出下一步操作o，o可以是问诊或检查，要求o能最大化获取2.或3.所需信息
5. 执行o，获取结果i，调用llm整理构造{o,g,i}，加入已知信息I
6. 重复1.-5.，直到达到最大轮数，或在2.中给出唯一疾病且不存在更多尚未确认的证据

- 以上过程中字母只是为了表示方便，在prompt中应使用更加明确清晰的表述
- 整理构造{o,g,i}时应适当进行精炼（在不丢失有效信息的前提下），避免上下文过长
