# 目标
在信息获取方式（指通过问诊、要求检查）**不变**的前提下，实现更高的准确率
严禁直接使用完整信息，信息获取流程必须跟普通doctor保持完全一致，仅优化处理信息的过程。 

# 设计
1. 调用llm，根据已知信息，给出数种可能的疾病种类。
2. 对1.中每种疾病，各调用一次llm（输入为该疾病名称），给出要确诊这种疾病所需进行的各种方法（问诊或检查，若为问诊，应限定格式，例如"Ask patient about {target_info}"）。对每种方法，还需要有重要性权值，表示该方法对确诊该疾病的影响力。对每种方法，还需要说明什么样的结果有助于确诊该疾病（例如阴性、阳性、数值范围等）
3. 对1.中每一对疾病，各调用一次llm（输入为这两种疾病名称），给出要区分这两种疾病所需进行的各种方法（问诊或检查，若为问诊，应限定格式，例如"Ask patient about {target_info}"）。对每种方法，还需要有重要性权值，表示该方法对区分这两种疾病的影响力。对每种方法，还需要说明不同的结果分别支持这两种疾病中的哪一种（例如阴性支持疾病A，阳性支持疾病B，数值范围等）
4. 对2.和3.中得到的多种方法，调用llm（输入为这些方法的列表），对这些方法名称的表述进行去重和归一化，同时统计实际为同一方法的次数，作为该方法的区分度权值。3.中的方法带来的权值应翻倍。工程实现上，应利用去重和归一化后的名称对原始名称进行替换，后续处理均使用归一化后的名称
5. 根据4.中得到的方法列表，根据重要性权值和与区分度权值的乘积进行排序，得到诊断计划
6. 对5.中诊断计划的第一项，若为问诊，则调用llm进行问诊（输入为情境和目标信息等）；若为检查，则不需要调用llm，直接输出检查请求（格式为"REQUEST TEST: [test]"）。完成后该项标记为已完成
7. 根据6.中得到的问诊结果或检查结果，以及之前在2.或3.中得到的该问诊或检查的结果判别方法，分别调用llm，对每种与此问诊或检查相关的疾病，给出该疾病与该问诊或检查结果的符合度（-100表示与此结果完全相反，0表示未确认或未知，100表示完全符合此结果）。对每种疾病，更新其确诊概率（confidence），计算方法为所有相关问诊或检查的符合度与重要性权值乘积之和再归一化，每种疾病的每个方法的初始符合度为0。若某种疾病的confidence超过某个阈值（例如90%），则该疾病确诊，输出诊断结果（格式为"DIAGNOSIS READY: [diagnosis here]"）
8. 根据6.中得到的问诊结果或检查结果，调用llm，更新合并已知信息
9. 根据8.中更新后的已知信息，重新进行1.，比较1.中得到的疾病种类列表与之前的疾病种类列表的差异，若新列表缺少的某种疾病目前的confidence低于某个阈值（例如-5%），则可认为此疾病已被排除，不再参与后续过程；若新列表中出现了某种新疾病，则对该疾病进行2.和3.中的处理（只需进行与差异部分即新出现的疾病有关的llm调用），更新方法列表和诊断计划
10. 若达到最大问诊次数时仍无法确诊，则结束流程，输出当前confidence最高的疾病作为诊断结果（格式为"DIAGNOSIS READY: [diagnosis here]"）

- llm的输出内容尽量结构化（如限制为json等格式），方便后续处理和维护。若输出不符合预期格式，应在尝试重新query几次后，抛出异常报错。
- 以上设计的实现，尽量不影响现有的agentclinic.py框架设计，保证与普通doctor的兼容性。
- 以上流程中，严禁直接使用完整信息，信息获取流程必须跟普通doctor保持完全一致，仅优化处理信息的过程。
